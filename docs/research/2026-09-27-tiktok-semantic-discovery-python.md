# TikTok semantic discovery and Python embedding research

**Research date:** 2026-09-27  
**Scope:** How semantic search fits the current Scout flow during migration to Python. This is research, not a specification or authorization for live collection.  
**Method:** Repository, SDD checkpoints, roadmap, changelog, and first-party TikTok, Qwen, Novita, and Google documentation. No account, token, live TikTok request, or performance benchmark was used for this research.

## Main finding

An embedding model can rank or search **candidate records that have already been acquired**. It cannot reveal videos that the acquisition route did not return. TikTok documents metadata filtering in its Research API, an authorized creator's own videos in its Display API, and rendering a known URL through oEmbed. None documents public-catalog semantic or vector search. [Research video query](https://developers.tiktok.com/docs/en/research-api-specs-query-videos); [Display video list](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-list); [oEmbed](https://developers.tiktok.com/docs/en/embed-videos).

The Research API cannot be assumed to replace Scout discovery for a commercial use case. TikTok says creators, advertisers, and commercial users are ineligible for its research tools; its published eligibility regions do not include Indonesia. Research Tools terms confine use to an approved proposal and include derivative works in Research Data. A particular Scout use and a persistent vector corpus require a separate entitlement and data-rights determination. This is a reading of published constraints, not a legal conclusion about the existing system. [Research FAQ](https://developers.tiktok.com/docs/en/research-api-faq); [eligibility](https://developers.tiktok.com/products/research-api/); [Research Tools terms](https://www.tiktok.com/legal/page/global/terms-of-service-research-api/en).

## Official TikTok routes

| Route | Documented capability | Fit and limit |
| --- | --- | --- |
| Research API `POST /v2/research/video/query/` | Filters include a keyword in `video_description`, hashtags, username, region, dates, length, and engagement. Selectable fields include description, hashtags, `voice_to_text`, creator, publication time, and counts. | Only for approved research. Each query covers at most 30 days and returns at most 100 records per page; pagination uses `cursor` and `search_id`. No vector-search parameter or downloadable media field is documented. [Query Videos](https://developers.tiktok.com/docs/en/research-api-specs-query-videos). |
| Research API freshness and quota | Standard quota: 1,000 requests and up to 100,000 records per day. New videos may take up to 48 hours to enter the index; metrics may take up to 10 days to refresh. | It cannot guarantee a live trend feed even for an eligible project. [Research FAQ](https://developers.tiktok.com/docs/en/research-api-faq). |
| Display API `POST /v2/video/list/` | Lists public videos of the user who granted OAuth `video.list`, newest first, at most 20 per page. | Consenting creator accounts, not broad cross-creator discovery. [List Videos](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-list). |
| TikTok oEmbed | Converts a **known video URL** to embed HTML and limited metadata. | Presentation or enrichment after discovery; no search or vector embedding. [Embed Videos](https://developers.tiktok.com/docs/en/embed-videos). |
| Commercial Content API | Queries ad-library and paid-partnership content under separate access and filters. | Narrower than organic video discovery. [Getting Started](https://developers.tiktok.com/docs/en/commercial-content-api-getting-started); [Query Commercial Content](https://developers.tiktok.com/docs/en/commercial-content-api-query-commercial-content). |

TikTok's [Developer Terms](https://www.tiktok.com/legal/page/global/tik-tok-developer-terms-of-service/en) restrict unauthorized database building over content and automated access outside documented permissions. [Research Tools terms](https://www.tiktok.com/legal/page/global/terms-of-service-research-api/en) require approved-project use and deletion of Research Data after termination. General [ROW Terms](https://www.tiktok.com/legal/page/row/terms-of-service/en) also restrict automated scripts. Vectorization alone does not establish permission to retain or reuse records. Google places responsibility for rights to uploaded content and resulting embeddings on the API user. [Gemini embedding guidance](https://ai.google.dev/gemini-api/docs/embeddings).

Existing SDD fixture captures already provide relevant page-behavior evidence; another live TikTok request was unnecessary for this research.

## Model and provider evidence

| Option | First-party evidence | Unresolved point |
| --- | --- | --- |
| Qwen3-Embedding-8B | Qwen describes 32K sequence length, 4,096 default dimensions, multilingual retrieval, and Matryoshka dimension reduction. Its examples distinguish instructed query embeddings from document embeddings. [Qwen repository](https://github.com/QwenLM/Qwen3-Embedding); [model card](https://huggingface.co/Qwen/Qwen3-Embedding-8B). | Model properties do not prove hosted availability, latency, price, or provider-exposed dimensions. |
| Novita hosted embeddings | Public `POST /openai/v1/embeddings` reference accepts one string or an array and lists `baai/bge-m3` as its model enum. [Novita API reference](https://novita.ai/docs/api-reference/model-apis-llm-create-embeddings). | It does **not** verify hosted `Qwen3-Embedding-8B` support. | Gemini `gemini-embedding-001` | Stable text model; 2,048-token input and 128–3,072 dimensions, with 768/1,536/3,072 recommended. Python `embed_content` can accept a list yielding separate vectors and supports retrieval task types. [Model page](https://ai.google.dev/gemini-api/docs/models/gemini-embedding-001); [guide](https://ai.google.dev/gemini-api/docs/embeddings). | Verify quota, billing, latency, and Indonesian relevance for the intended account. |
| Gemini `gemini-embedding-2` | Stable multimodal model for text, image, video, audio, and PDF; 8,192-token input and 128–3,072 dimensions. Current paid text pricing is $0.20 per million input tokens synchronously and $0.10 through Batch. [Model page](https://ai.google.dev/gemini-api/docs/models/gemini-embedding-2); [pricing](https://ai.google.dev/gemini-api/docs/pricing). | Multiple inputs in one `embed_content` call are **aggregated into one** vector. Per-video vectors require separate requests or Batch. Batch targets completion within 24 hours, so it suits offline refresh rather than an interactive query. [Guide](https://ai.google.dev/gemini-api/docs/embeddings); [Batch API](https://ai.google.dev/gemini-api/docs/batch-api). |

Provider documentation does not establish end-to-end Scout latency, throughput, or top-k relevance. A text vector cannot recover a fact absent from caption or hashtags. Python's `DiscoveredVideo` has no transcript or frame description; the Research API's `voice_to_text` field does not mean the current browser path captures it.

## Python fit: hypothesis to test

Compare a **literal metadata baseline** with semantic reranking of the **same authorized candidate set** from Python discovery. For the current result of at most 100 videos per request, exact cosine comparison in process is a reasonable baseline. An approximate-nearest-neighbor service is justified only if a permitted corpus and measured latency require it; deletion and re-embedding after changes to text, model, or permission would then matter. This is a scaling hypothesis, not a measured threshold.

Label representative Indonesian story queries and candidate videos, including casual creator captions that differ from news-style wording. Compare judged top-k relevance (such as recall@k and nDCG), missing-caption and duplicate rates, and false positives. Measure p50/p95 separately for TikTok page acquisition, enrichment, embedding API, and local ranking; also record request count, token cost, block rate, and freshness. Moving orchestration to Python alone does not establish faster browser access, better quota, or higher recall.

If rights allow derived vectors to persist, test embedding each document when its text changes and each query once, against Scout's per-ranking-call embedding pattern. Keep query/document instructions, model, dimensions, and normalization consistent within each evaluation. Preserve the literal/metadata fallback if the provider is unavailable. Do not import Scout's footage similarity floor into TikTok search without labeled evidence. Multimodal video embeddings are a later comparison only if media access, rights, and text-first error analysis justify them.

## Open evidence questions

1. Which current acquisition routes, if any, permit retaining metadata and derived vectors for this product use? Published API pages do not settle rights over records obtained by other means.
2. What are the permitted corpus size, Indonesian language mix, caption/transcript coverage, freshness needs, and acceptable recall? No representative benchmark was run here.
3. Is `qwen/qwen3-embedding-8b` available at the configured Novita endpoint/account, and with what limits, dimensions, latency, and price?
4. Does semantic reranking improve judged results over the current literal/metadata baseline on the **same** candidates? If not, expanding candidate acquisition or improving non-text evidence may matter more than changing models.
