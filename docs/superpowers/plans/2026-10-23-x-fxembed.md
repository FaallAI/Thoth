# X via FxEmbed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring X back to life signed out by reading FxEmbed:
- every video of an X post;
- replies (comment cards), views/reposts and long text;
- profile media listings (attribution, creator footage and photos);
- multi-video F2 footage;
- shape-anchored profile cards.

**Architecture:** A small FxEmbed client and pure parsers replace the dead page-JSON enrichment (`XAcquirer._page`) and the profile page parse (`XProfileDiscovery`). Both return the same models as today (`XPageParse`, `DiscoveryResult`), so the callers barely change. Syndication stays the core and the fallback.

**Tech Stack:** Python 3.12, pydantic, the existing Scrapling GET helper (`_scrapling_get`, `REQUEST_OPTIONS`), Playwright/Chromium for card crops, pytest.

**Spec:** `docs/superpowers/specs/2026-10-23-x-fxembed-design.md`

## Global Constraints

- FxEmbed base URL setting: `THOTH_X_FXEMBED_URL = "https://api.fxtwitter.com"`. Endpoints:
  - `GET /2/status/{id}`;
  - `GET /2/conversation/{id}`;
  - `GET /2/profile/{handle}/media?count=N`.
- No X account is ever leased for X profile listings, post enrichment or cards (spec non-goal).
- The main still follows 5a A2. Multi-video X posts follow 5b F2 (the first video is the main; the rest are footage, at most `MAX_FOOTAGE`).
- No synthetic cards. A reply the page does not render stays a text comment (`card=None`).
- Every fallback logs a warning with a reason. Never log FxEmbed bodies.
- Keep `page_tweets` and everything `footage/adapters/x_search.py` imports.
- Commits: one-line subject via `git commit -m "<subject>"`. No body, no trailer, no AI attribution. Never stage `.superpowers/`, `graphify-out/`, `.serena/`, `design/`.
- Test commands run from WSL at the worktree root (`/mnt/d/thoth-tmp/wt-x`):
  - **Unit:** `bash scripts/dev/pytest-wsl.sh <path>`;
  - **Browser-backed:** `WT=/mnt/d/thoth-tmp/wt-x bash /mnt/d/thoth-tmp/browser-tests.sh <path>`;
  - **Lint:** `make lint`.
- Live gates (Task 0, Task 7) are authorised by the operator (2026-10-23). Rules:
  - anonymous only, never an account, cookie or proxy;
  - at least 30 s between requests;
  - record every request (UTC, URL, outcome) in `D:/thoth-tmp/research/x-fxembed/live-log.md`.

## Review Focus

1. **Videos and order.** A post whose FxEmbed status has videos but whose syndication lists a
   different number of video entries must keep every FxEmbed video in FxEmbed order, never drop
   all of them. Task 2 pins it.
2. **Replies that are not replies.** An FxEmbed reply whose `replying_to` is another status (a
   reply to a reply), or whose author is missing, must be dropped and counted, not carded.
   Task 1 pins it.
3. **Thin X listings.** A thin or empty X listing (fewer than `THIN_LISTING`) must not lease an
   X account, in any access mode. Task 3 pins it.
4. **Videos count first.** A profile media post with both photos and a video counts as a video
   post, never a photo post. Task 1 pins it.
5. **No-text profile hits.** The profile-card tag JS must tag nothing when `@owner` is absent (a
   wrong or suspended page), so no card is cropped. Task 5 pins it.

**Interfaces:**
- Produces, in `adapters/fxembed.py`:
  - `fx_videos(status: dict) -> list[str]`: the best MP4 per video, in order. Rule: from `formats` with `container == "mp4"`, the highest `bitrate`; else `url` when it ends in `.mp4` (query ignored).
  - `fx_engagement(status: dict) -> dict[str, int]`: keys `like`, `comment`, `share`, `play`, from `likes`, `replies`, `reposts`, `views`; non-int values skipped.
  - `fx_text(status: dict) -> str | None`: `raw_text.text` if it is a str, else `text`.
  - `fx_page(status: dict | None, replies: list[dict], post_id: str) -> XPageParse` (`XPageParse` from `adapters/x.py`).
  - `fx_profile(payload: dict | None, handle: str, limit: int) -> DiscoveryResult` (models from `acquisition/models.py`; `rank_videos` from `instagram_discovery`; `MAX_CAPTION` and `_empty` from `discovery`).
- Produces, in `x_fxembed.py`, `class FxEmbedClient`:
  - `__init__(self, get: Callable[..., Awaitable[Any]] | None = None, base_url: str | None = None)`. Defaults: `_scrapling_get` and `settings.THOTH_X_FXEMBED_URL`.
  - `async status(post_id: str) -> dict | None`
  - `async replies(post_id: str) -> list[dict]`
  - `async profile_media(handle: str, count: int) -> dict | None`
  - Raises `RequestFetchError` (from `threads_service`):
    - transport timeout → `AcquisitionReason.REQUEST_TIMEOUT`;
    - any other transport error, HTTP 429, or 5xx → `REQUEST_BLOCKED`. The warning logs the HTTP status.
  - Returns None (or `[]`) for HTTP 404, `code == 404`, or unreadable JSON. Unreadable JSON logs a warning `x fxembed unreadable`.
  - Sends the header `User-Agent: Thoth/1.0 (+https://github.com/FaallAI/Thoth)` merged into `REQUEST_OPTIONS`, if the GET helper accepts headers; otherwise ledger a ruling.
